Lesson 6 · Permissions and Data Security

Using AI responsibly at work starts with knowing what it can actually access.

What you'll learn

  • The different permission modes an AI tool can operate under, and what each one actually grants
  • How the same task changes depending on which permissions are turned on
  • How to request connector access from your company's IT team without slowing everything down

Concept

What your AI tool can reach, and who has to sign off

Two things decide what an AI tool can do on your behalf: which permissions you've turned on, and which ones your company allows in the first place.

Permissions

An AI tool can operate under a few distinct access modes: tool use (calling a specific built-in function, like a calculator), web access (searching or browsing the live internet), computer or desktop control (taking actions on your screen directly), and data or file access (reading a file you upload or a drive you've connected). Each one is a separate grant. Turning one on doesn't turn the others on.

The idea in one line

|

Company constraints

Most workplaces don't let an AI tool touch company systems by default. Getting a connector approved, like a shared drive or a ticketing system, usually means asking IT first. A specific, scoped request gets answered faster than a vague one.

  • Granting web access doesn't grant file access, or the reverse. Check each one separately before you assume what a tool can see
  • A tool with computer control can click and type on your actual screen, which is a bigger grant than it sounds like at first
  • When requesting IT access, naming exactly what data the connector would touch speeds up approval more than anything else you can say

Build 1 · Permissions

Turn on web access and compare

Open your AI tool of choice. Check whether it has a web search toggle, and whether it offers a Chrome extension. Most major tools have at least one of the two.

First, try this with web search turned on. Then turn it off and ask the same thing again.

What's the latest news on [a topic you care about]? Include links to your sources.
Why this matters to notice

With web access on, the model can pull in information from outside its training data and tell you where it came from. With it off, it can only work with what's already in the conversation, so it either declines or guesses from older training data.

Next, if your tool has a Chrome extension (Claude and ChatGPT both ship one), install it and ask it to summarize the actual page you're currently looking at. Notice it can now see the live page, not just text you paste in.

🔧 Troubleshooting: no web search toggle or extension

Not every plan includes it. Check your tool's settings menu for a toggle labeled "search" or "browsing," or check the Chrome Web Store directly for your tool's name, since extensions are sometimes released separately from the main product.

Build 2 · Company constraints

Draft a real IT request

Before drafting anything, spend five minutes on the audit: list every AI tool and connector you're currently approved to use at work. Check your admin console, your team's tool list, or just ask IT directly. Then pick one connector you don't have yet but actually want.

Copy the template below and fill in the brackets for that connector.

Subject: Access request: [tool or connector name] for [your name / team]

Hi [IT contact / IT team],

I'd like to request access to [tool or connector name, e.g. "the shared drive connector in Claude"].

What it's for: [one sentence, e.g. "so it can summarize meeting notes stored in our shared drive instead of me copying them in by hand each week"].

What data it would touch: [be specific and scoped, e.g. "read-only access to the Marketing shared drive. It would not need edit access, and it doesn't need to touch Finance or HR drives"].

Who else should weigh in: [e.g. "looping in my manager, [name], and our security contact if there's a review step"].

Happy to fill out whatever approval form this needs. Thanks!
Why this template works

Naming exactly what data the connector would touch, and scoping it down (read-only, one drive, not everything), is what lets an IT reviewer approve fast. A vague "can I get AI access to our systems" request usually bounces back with questions instead.

Send it, or save the draft if you're not ready to send it yet. Either way, you'll have a real request instead of a hypothetical one.

🔧 Troubleshooting: not sure who to send it to

Check your company's IT ticketing system first. If there isn't an obvious owner, ask your manager who approves new tool or connector requests.

Stretch (optional)

Go further (optional)

Not required, but worth trying if you've got a few more minutes.

⚡ Draft a second IT request 
Reuse the template from the last page for a different connector, e.g. a Slack integration, a CRM, or a ticketing system. Fill in what data it would touch and who should weigh in, same as before.
⚡ Run the audit for a teammate 
Ask a teammate what tools and connectors they currently have approved at work. Compare that against what they actually use day to day, and help them spot one gap worth requesting.
